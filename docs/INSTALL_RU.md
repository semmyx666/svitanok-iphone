# Установка: подробно и без обещания «архив сам установится»

## 1. Выберите путь

**Есть Mac:** собирайте и устанавливайте через Xcode по инструкции ниже. Это основной путь.

**Только Windows/Linux:** локальный Xcode здесь не запускается, но можно использовать включённую бесплатную macOS-сборку GitHub Actions и затем локальную подпись на Windows. См. WINDOWS_FEDORA_FREE_RU.md. TestFlight — вариант распространения после macOS-сборки и регистрации в Apple Developer Program, а не способ превратить ZIP в приложение. Android пока не заменяем веб-страницей.

**Только iPhone и Telegram:** ZIP можно хранить и пересылать как документ, но установить приложение простым нажатием на ZIP нельзя. Developer Mode не отменяет подпись и provisioning profile. IPA тоже должен быть правильно подписан подходящим способом; обычное сохранение IPA в «Файлы» не устанавливает его.

## 2. Подготовка Mac

1. Установите Xcode 26+ из официального источника Apple; при необходимости совместимую версию macOS. Откройте Xcode, примите лицензию, установите компоненты и iOS 26+ Simulator.
2. В Xcode → Settings → Accounts добавьте **свой** Apple Account. Пароль вводится только в официальном интерфейсе Apple, не в чат.
3. В настройках iPhone проверьте iOS 26+, Developer Mode уже включён. Если версия ниже — этот прототип не подходит.
4. Если Homebrew отсутствует, установите его по официальной инструкции https://brew.sh/ . После этого:

```bash
brew install xcodegen
xcodebuild -version
```

Если CLI выбрал не тот Xcode:

```bash
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
```

Путь может отличаться, если ваша программа Xcode называется иначе.

## 3. Распаковка и создание проекта

Перешлите ZIP в Telegram **как файл**, скачайте его на Mac. В терминале перейдите в папку со скачанным архивом:

```bash
cd ~/Downloads
unzip Svitanok-iPhone-v0.2.zip
cd Svitanok
xcodegen generate
open Svitanok.xcodeproj
```

Или из корня распакованного проекта:

```bash
bash scripts/prepare_mac.sh
```

В Xcode выберите target **Svitanok** → Signing & Capabilities:

- включите Automatically manage signing;
- выберите свою Team;
- задайте уникальный Bundle Identifier, например `ua.yourname.svitanok` — замените `yourname`, не используйте чужой идентификатор;
- проверьте iOS Deployment Target 26.0.

С бесплатной Personal Team возможны ограничения и короткий срок подписи; ориентируйтесь на фактический срок provisioning profile в Xcode. После истечения приложение потребует переподписи. Для будильника это дополнительный риск. Платная программа разработчика нужна для некоторых способов распространения, например TestFlight; покупать её для первого локального теста не следует автоматически.

## 4. Первое подключение и затем Wi-Fi

Для обычного сопряжения iPhone с Xcode Apple описывает первое подключение кабелем:

1. Подключите iPhone к Mac, разблокируйте и подтвердите «Доверять этому компьютеру».
2. В Xcode откройте Window → Devices and Simulators / Manage Devices (название зависит от версии).
3. Дождитесь окончания pairing и подготовки устройства. В версиях Xcode с переключателем Connect via network включите его.
4. Mac и iPhone должны находиться в одной подходящей Wi-Fi-сети; для актуального беспроводного соединения Apple указывает IPv6. VPN/изоляция клиентов сети могут мешать обнаружению.
5. Когда iPhone доступен Xcode, кабель можно отсоединить и запускать сборки по Wi-Fi. Если устройству нужна повторная доверенная связь, потребуется восстановить сопряжение.

**Не обещаем полностью беспроводную первую установку.** Если Mac и iPhone уже сопряжены, начните с проверки доступности устройства без кабеля.

Выберите iPhone в списке устройства запуска и нажмите **⌘R**. Если iOS попросит доверять разработчику, используйте Settings → General → VPN & Device Management и следуйте подсказкам. Это не отменяет необходимости Developer Mode и действительной подписи.

## 5. Команды сборки и установки на уже сопряжённый iPhone

Сначала получите UDID, который Xcode использует как run destination:

```bash
xcrun xctrace list devices
xcrun devicectl list devices
```

Второй список полезен для проверки доступности. Не путайте device name с UDID; в разных инструментах могут также показываться внутренние UUID. Используйте UDID вашего iPhone из Xcode / xctrace для скрипта.

TEAM_ID — идентификатор вашей команды из Apple/Xcode, не адрес электронной почты и не пароль. Замените строки в кавычках своими значениями:

```bash
export TEAM_ID="YOUR_TEAM_ID"
export BUNDLE_ID="ua.yourname.svitanok"
bash scripts/install_device.sh "YOUR_IPHONE_UDID"
```

Скрипт вызывает `xcodegen`, `xcodebuild`, `devicectl install` и `devicectl launch`. Он требует, чтобы ваш аккаунт уже был добавлен в Xcode, а устройство сопряжено и доступно. Никакие пароли в скрипт не передаются.

Если автоматическая подпись/сопряжение возвращают ошибку — используйте Xcode GUI, устраните указанную ошибку, не отключайте проверки безопасности и не устанавливайте случайные сертификаты.

## 7. Реальные данные тревог: ваш сервер

Для обычного системного будильника сервер не нужен. Для статуса области и экспериментального переноса нужен токен alerts.in.ua и постоянно доступный HTTPS-сервер. Карта сайта использует своё соединение независимо от вашего прокси.

1. Подайте заявку: https://alerts.in.ua/api-request . Выдача токена не мгновенная и не гарантирована.
2. Подготовьте **свой** Linux-сервер с Docker Engine и Docker Compose plugin. Хостинг/домен могут стоить денег, ничего не закуплено и не развёрнуто от вашего имени.
3. Привяжите поддомен, например `alerts.example.com`, DNS A/AAAA к серверу. Если IPv6 на сервере не работает, не создавайте неверную AAAA-запись.
4. Откройте входящие TCP-порты 80 и 443 для Caddy. Не публикуйте порт Python 8080 в интернет. Порт SSH нужен вам для администрирования.
5. Скопируйте каталог `server` из архива на сервер. В Bash из этого каталога создайте приватный `.env`:

```bash
read -r -s -p "API-токен alerts.in.ua: " token; echo
read -r -p "Поддомен сервера (без https://): " domain
umask 077
printf 'ALERTS_TOKEN=%s\nALERTS_DOMAIN=%s\n' "$token" "$domain" > .env
unset token domain
chmod 600 .env
docker compose up -d --build
docker compose ps
```

Токен вводится скрыто. `.env` не добавляйте в Git, не пересылайте вместе с архивом и не присылайте в чат. Примерный домен надо заменить реальным. Caddy получит HTTPS-сертификат, если DNS/порты корректны.

Проверьте именно данные, не только liveness:

```bash
curl --fail --show-error https://alerts.example.com/health
curl --fail --show-error https://alerts.example.com/v1/status
```

Снова замените домен. Во втором ответе должны быть `fetchedAt`, 27 `statuses` и `source: "alerts.in.ua"`. `503` означает, что свежие данные не получены; это НЕ отбой. Проверить доступность живого API и его токен здесь не удалось.

В приложении → Настройки → Источник данных впишите только origin, например `https://alerts.example.com` (без `/v1/status`, без токена и пароля). Выберите регион и обновите статус. Частичные тревоги учитываются консервативно для всей области. Точность до отдельной громады в этой версии отсутствует.

Сервер выполняет максимум примерно 4 запроса в минуту независимо от числа клиентов, кеширует 15 секунд, при ошибках увеличивает паузу до 5 минут. Клиент отвергает данные старше 45 секунд. API сам может задерживаться — возраст HTTP-ответа не гарантирует отсутствие задержки в первоисточнике.

Для долгосрочного/публичного использования дополнительно нужны мониторинг, обновления сервера, защита от DDoS, ревизия условий источника и отдельная оценка надёжности. В комплекте небольшой прототип, не production-инфраструктура.

## 8. IPA и TestFlight — позже, с вашей подписью

После успешных тестов на реальном телефоне можно создать archive на Mac:

```bash
xcodebuild -project Svitanok.xcodeproj \
  -scheme Svitanok -configuration Release \
  -destination 'generic/platform=iOS' \
  -archivePath build/Svitanok.xcarchive \
  -allowProvisioningUpdates \
  DEVELOPMENT_TEAM="$TEAM_ID" \
  PRODUCT_BUNDLE_IDENTIFIER="$BUNDLE_ID" archive
open build/Svitanok.xcarchive
```

В Xcode Organizer используйте **Distribute App** и подходящий способ подписи/экспорта. Доступные варианты зависят от вашей Team и зарегистрированных устройств. Экспорт IPA не даёт права установить его на любой iPhone. Для TestFlight нужны платное членство, запись приложения в App Store Connect, загрузка сборки и возможная проверка Apple.

Отправка такого файла в Telegram — передача файла, не механизм установки. Мы не создавали enterprise-сертификатов, App Store-публикации или профилей обхода ограничений.

## 9. Настройка перед первым утром

1. Оставьте независимый резерв в «Часах».
2. Сначала используйте обычный режим и тест через 2 минуты при заблокированном экране.
3. Проверьте разрешение AlarmKit, звук, громкость, батарею и зарядку.
4. Экспериментальный перенос включайте лишь для контролируемого дневного испытания, не перед школой.
5. Назначьте конкретную дату/время. Это **один** будильник, не повтор каждое утро.
6. Изменение области или звука после установки не меняет текущий сигнал: отключите и установите заново.
7. При сигнале нажимайте «Я проснулся»: действие должно убрать связанные сигналы, в том числе резерв. Проверьте это на устройстве до использования.
