# Світанок 0.7 — что проверено

Сборка: https://github.com/semmyx666/svitanok-iphone/actions/runs/38968105991
Исходный код сборки: 93c1c0e. Xcode 26.6, iPhone 17 Pro Simulator.
IPA: ARM64 iPhoneOS, версия 0.7.0 (7), минимум iOS 26.0, bundle ua.semmyx.svitanok.

## Успешные проверки
- 136 Swift unit tests: 0 ошибок. Включены 23 проверки парсинга API/Keychain и 5 проверок HTTP-транспорта/ограничения запросов.
- 6 UI tests: 0 ошибок. Ввод тестового ключа, сохранение в настоящем Keychain симулятора, завершение и повторный запуск приложения, наличие ключа после запуска, удаление.
- Ещё 2 отдельных UI-сценария: ночной искусственный отбой после фактической блокировки симулятора и математический пример с повторным системным звонком после блокировки.
- Ночная проверка подтвердила фоновые запросы и AlarmKit alerting после искусственного отбоя.
- Серия подтвердила три сигнала, неверный ответ без отмены, три подтверждённых повтора после правильного ответа и после вызова Stop-обработчика, ноль оставшихся сигналов после полного завершения.
- 81 Python backend + 20 packaging тестов: 0 ошибок.
- Версия, структура IPA, ARM64-заголовок и SHA256 сверены. Два снимка раздела ввода/сохранения ключа просмотрены.

## Чего эта проверка НЕ подтверждает
- Использовались вымышленные тестовые ключи и ответы API. Настоящий личный токен пользователя не отправлялся из CI, не помещался в исходники и не встроен в IPA. Реальное подключение проверяется на iPhone кнопкой «Проверить токен и подключение».
- Это не ночное испытание физического iPhone 13, реального динамика, реальных тревог или реального отбоя.
- В тесте повторов интервал 15 секунд; в обычных настройках минимум 5 минут.
- Stop-обработчик вызван тестом через тот же LiveActivityIntent, а не физическим нажатием Stop на экране блокировки.
- Ночное ожидание по-прежнему требует звука для сна. Прерывание фоновой работы/сети не превращается в отбой; резерв может прозвенеть во время тревоги.
- Системную кнопку Stop iOS убрать нельзя. Математический пример относится к действиям внутри приложения.

## Подпись и безопасность
Симуляторная сборка подписана Xcode локально ad-hoc (без платного сертификата); тестовые iOS-разрешения внедрены штатным способом только в симулятор. Этот тестовый идентификатор отсутствует в iPhone IPA. Установочный IPA намеренно не подписан: подпись вашим Apple ID выполняет iloader на Fedora.
Ключ на устройстве хранится в Keychain с kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly, не синхронизируется через iCloud. В API передаётся в заголовке Authorization, не в URL. Redirect не разрешён. Тестовое/пользовательское хранилища UserDefaults ключа не содержат.

Документация источника: https://devs.alerts.in.ua/
Личный прямой доступ не означает разрешение публично распространять общий ключ. Для публичного сервиса правила источника требуют прокси.
