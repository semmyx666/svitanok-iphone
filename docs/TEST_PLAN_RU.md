# Проверки и границы доказанного

## Что действительно выполнено в среде подготовки

- 64 автоматических теста Python на синтетических данных: парсинг A/P/N и всех 27 позиций; неверные типы/размер/кодировка; кэш; непереиспользование устаревшего «отбоя» при ошибке; тайм-аут; backoff; HTTP 429; отсутствие токена в логах; конкурентные запросы; реальные локальные HTTP-запросы к тестовому серверу.
- Дополнительно 20 тестов упаковки IPA: ARM64-заголовок, device/simulator, Info.plist, права исполняемого файла, ошибки входных данных, ZIP-структура. Это тестовые заголовки, НЕ работающие iOS-приложения.
- Повторный прогон обоих наборов (64 + 20) 20 раз: результаты в `backend-repeat-summary.json`. Это 1680 прохождений тестов сервера/упаковки, не испытания iPhone.
- Скрипт визуального макета проверен в Chromium при мобильном и широком размерах; картинки — HTML-макет, не снимки работающего iOS-приложения.
- Проверены синтаксис Python, Bash, структура ресурсов и конфигурации проекта. Это НЕ Swift-компиляция.

## Что подготовлено, но НЕ выполнено

35 XCTest-тестов настоящей Swift-политики. Один тест перебирает 40 992 сочетания состояний/времени/резерва/активности. Пока `scripts/test_ios.sh` не пройдёт на Mac, это лишь подготовленные тесты, а не доказательство правильности iOS-приложения.

**Не выполнены:** сборка Xcode; работа AlarmKit на устройстве; разрешения; звук в silent/focus; поведение при перезагрузке/force-quit; реальный API; деплой сервера; телефонная установка; обработка крайних состояний фоновых App Intents. Такие результаты нельзя подменять тестами Python.

## Запуск Python-проверок

Из корня проекта:

```bash
python3 -m unittest discover -s server/tests -v
python3 -m unittest discover -s scripts/tests -v
python3 scripts/repeat_backend_tests.py
```

Тесты не требуют токена и не обращаются к настоящему API. Поддельные ответы используются только в тестах, не в приложении. Все строки с `fake` или тестовым значением токена — фикстуры.

## Обязательный реальный iPhone: сначала днём

Для каждого случая запишите модель телефона, iOS, сборку Xcode, время постановки, фактическое время сигнала и результат. Не делайте первые испытания перед школой.

| Сценарий | Ожидание / что проверить |
|---|---|
| Первое открытие без разрешения AlarmKit | Не показывать успешную установку без разрешения. |
| Обычный тест через 2 минуты, приложение открыто | Системный сигнал около назначенного времени; кнопка «Я проснулся» останавливает сигнал. |
| Обычный тест, экран заблокирован | Системный сигнал от AlarmKit, не JavaScript/таймер приложения. |
| Обычный тест, приложение смахнуто | Проверить, что ранее установленный системный сигнал сохраняется; записать реальное поведение. |
| Беззвучный режим / Focus | Проверить громкость, слышимость, отображение системного сигнала. AlarmKit предназначен для prominent alarm, но фактическое поведение надо проверить. |
| Airplane Mode, сервер не настроен | Обычный сигнал работает без сети. Перенос не подтверждается. |
| Разрешение отозвано после установки | Убедиться, что UI не вводит в заблуждение; повторно проверить доступность системного сигнала. |
| Настройки звука «Рассвет» и «Импульс» | Предпрослушивание + настоящий системный сигнал каждой мелодией; не считать предпрослушивание проверкой AlarmKit. |
| Перезагрузка до сигнала | Отдельно проверить сохранение системного расписания и работу до/после первого разблокирования. |
| Малая батарея / Low Power Mode | Обычный сигнал и ограничения обновлений; разряженный/выключенный телефон не обещает сигнал. |
| Область Kyiv vs м. Київ | Не смешивать регионы. Проверить вывод правильного индекса. |
| Активная/частичная тревога, приложение активно | В окне 30–3 с до времени основной сигнал отменяется ТОЛЬКО при установленном резерве; UI сообщает перенос. Используйте контролируемый тестовый стенд, не подменяйте живые данные. |
| Нет сети до проверки | Основной сигнал не снимается. |
| Ответ просрочен >45 с или из будущего >5 с | Статус unknown, основной сигнал не снимается. |
| 401/403/429/500 или повреждённый JSON | Статус unknown, основной сигнал не снимается. |
| Ошибка установки резерва | Основной не должен автоматически переноситься; UI сообщает неполную установку. |
| Ошибка отмены основного | Не показывать подтверждённый перенос, если отмена не удалась. |
| Тревога окончилась после назначенного времени, приложение активно | После свежего clear-ответа появляется системный сигнал через ~5 с; учитывать задержку polling/сети/источника. |
| clear пришёл до назначенного времени после переноса | Не будить раньше назначенного времени. Следующая проверка после него запускает сигнал. |
| Интернет пропал после уже выполненного переноса | Резерв в предельное время сохраняется; мгновенное восстановление исходного времени не обещается. |
| Экран заблокировали после переноса | Немедленный сигнал после отбоя не гарантируется. Резерв должен остаться системным. |
| Тревога продолжается до предельного времени | Резерв всё равно звонит. Это не уведомление «можно выйти». |
| «Я проснулся» на основном / отбойном / резервном сигнале | Проверить каждый из трёх вариантов: связанные сигналы группы отменены, через время резерва нет неожиданного дубликата. |
| Отключение в приложении | Все сигналы текущей группы отменяются. Ошибки отмены показаны пользователю. |
| Отмена через системный интерфейс без app intent | Проверить остаточные сигналы. До подтверждения нельзя считать все пути отмены эквивалентными. |
| Изменение настроек при активном будильнике | Текущий сигнал не меняется молча. Нужны отключение и повторная постановка. |
| Смена часового пояса / DST | Время fixed хранится как конкретный момент; UI показывает локальный пояс iPhone. Установить заново при изменении планов. |
| Длительная работа / смена дня | Это один сигнал. Автоматического повторения на следующий день нет. |
| Срок подписи истёк | Проверить профиль; не рассчитывать на приложение после истечения без переподписи. |
| Карта без интернета / сайт запретил embedding | Показывается ошибка или используется Safari, без выдуманной карты. |

## Критерий готовности

Не считать эту версию готовой для повседневного школьного будильника до успешной Xcode-сборки и многократных испытаний физического устройства. Даже после испытаний сетевой источник и ограничения iOS не дают абсолютной гарантии. Гарантированный ночной условный перенос в данном прототипе не является достигнутым критерием.
