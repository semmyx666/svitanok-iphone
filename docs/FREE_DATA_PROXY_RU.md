# Данные тревог: бесплатно, без VPS и покупки домена

Это тестовый вариант: собственный ПК запускает Python-прокси, а бесплатный **Cloudflare Quick Tunnel** даёт ему временный HTTPS-адрес. Аккаунт Cloudflare/покупка домена для команды Quick Tunnel не требуются. Услуга не предоставляет SLA и предназначена для разработки/тестирования, не для обещаний круглосуточной надёжности.

Компьютер должен оставаться включённым, без сна, с интернетом; оба процесса должны работать. После перезапуска туннеля адрес может измениться: заново впишите его в приложение. Если ПК уснул или туннель упал, свежие статусы не поступают. В обычном режиме уже поставленный системный будильник не зависит от этого ПК. Перенос запрещается при отсутствии данных; ранее выполненный перенос сохраняет предельный резерв.

## 1. Токен источника

Подайте заявку https://alerts.in.ua/api-request . Токен выдаётся источником, не мной; его здесь нет. Условия и доступность надо проверить у источника. Введите токен только в локальный скрытый запрос скрипта. Не отправляйте его в чат, Telegram, GitHub или Sideloadly. API-токен и Apple Account — совершенно разные вещи.

## 2. Windows

Установите Python и официальный cloudflared:

```powershell
winget install --id Python.Python.3.13 --exact
winget install --id Cloudflare.cloudflared --exact
```

Откройте новое окно PowerShell, перейдите в распакованный корень `Svitanok`. Прочитайте `scripts/start_free_proxy.ps1`: он запускает только ваш локальный сервер и туннель. Если Windows пометила скачанный файл как заблокированный, разблокируйте **этот проверенный вами файл**, не отключайте политики безопасности глобально:

```powershell
Unblock-File .\scripts\start_free_proxy.ps1
powershell -NoProfile -File .\scripts\start_free_proxy.ps1
```

Если ваша организация запрещает выполнение таких скриптов, не обходите её правила. Код скрипта использует скрытый ввод `Read-Host -AsSecureString`, кратковременно передаёт API-токен только в окружение Python-дочернего процесса, удаляет его из окружения родительского процесса перед запуском туннеля и не сохраняет токен в файл. PowerShell-сценарий подготовлен, но в Windows здесь не запускался.

## 3. Fedora

Установите Python/curl и cloudflared из официального репозитория выпуска Cloudflare:

```bash
sudo dnf install -y python3 curl
mkdir -p "$HOME/.local/bin"
case "$(uname -m)" in
  x86_64) ARCH=amd64 ;;
  aarch64) ARCH=arm64 ;;
  *) echo 'Эта архитектура не описана в инструкции'; exit 1 ;;
esac
curl --fail --location --proto '=https' --tlsv1.2 \
  "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-$ARCH" \
  -o "$HOME/.local/bin/cloudflared"
chmod +x "$HOME/.local/bin/cloudflared"
export PATH="$HOME/.local/bin:$PATH"
cloudflared --version
```

Бинарник стороннего инструмента получайте только из официального проекта; при необходимости сверяйте контрольную сумму с данными выбранного release. Эта инструкция не запускает чужой shell-скрипт через `curl | sh`.

Из корня проекта:

```bash
bash scripts/start_free_proxy.sh
```

Токен вводится скрыто. Скрипт не передаёт его в аргументе командной строки и не сохраняет на диск. После выхода туннеля останавливает запущенный им Python-процесс. Реальное подключение к API/Cloudflare здесь не проверялось.

## 4. Проверка и подключение телефона

cloudflared напечатает адрес вида `https://random-name.trycloudflare.com`. Это пример формы адреса — конкретное имя выдаёт ваш туннель.

На Windows:

```powershell
Invoke-RestMethod "https://ВАШ-АДРЕС.trycloudflare.com/v1/status"
```

На Fedora:

```bash
curl --fail --show-error 'https://ВАШ-АДРЕС.trycloudflare.com/v1/status'
```

Замените `ВАШ-АДРЕС` реальным поддоменом. Должны быть `fetchedAt`, 27 `statuses` и `source: alerts.in.ua`. `503`, ошибка токена, тайм-аут и HTML-страница ошибки — НЕ отбой.

В приложении → Настройки → Источник данных впишите **только origin**: `https://реальный-поддомен.trycloudflare.com`, без `/v1/status`, параметров, токена и пароля. Выберите область, обновите статус. API имеет свою задержку; новый HTTP-ответ не доказывает отсутствие задержки в первоисточнике.

Адрес туннеля публично доступен: отдаёт статусы регионов, не API-токен. Cloudflare видит сетевой трафик к сервису. Не подключайте этим туннелем другие приватные приложения или весь рабочий стол. Здесь проксируется только сервер на `127.0.0.1:8080`.

Документация: https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/
